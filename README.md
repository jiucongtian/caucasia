# CAUCASUS · 高加索汽配采购 Demo

基于 [采购端需求 V0.1](srs/采购端需求-V0.1.md) 实现的可操作 Web 演示。

## 运行

需要 Node.js 20 或更高版本，无需安装第三方运行依赖。

```sh
npm run dev
```

打开 `http://127.0.0.1:5173`。服务默认仅监听本机。

```sh
npm test
npm run check
```

如需更换端口：`PORT=5174 npm run dev`。

## 演示流程

1. 右上角切换汽修店、经销商、直营店，对比同款商品价格。
2. 搜索 `04465-33480` 或配件名称，通过品牌和车型筛选商品。
3. 打开商品详情或直接加购，编辑采购数量。
4. 在采购清单确认商品后，选择配送或自提并提交。
5. 打开订单，依次模拟付款、核账和物流节点。混合订单按现货与预售分别履约。
6. 查看智能拼柜的两种方案及运营大屏。

## 已实现

- 三种预设买家身份，独立的购物车、订单与收货信息。
- 8 款示例汽配，分类、关键词、OE、品牌及车型检索与价格排序。
- 角色定价、库存数量限制、购物车修改与删除。
- 现货／预售混合采购，一张采购订单、分组履约。
- 配送／自提、收货表单校验、订单金额计算和成功页。
- 订单筛选、下单成交价快照、模拟付款核账与履约时间轴。
- 浏览器本机持久化，刷新保留记录。
- 两个假设拼柜批次、立体装箱示意、装载率与方案对比。
- 独立深色运营大屏、渠道分布、货源结构、采购趋势及批次进度。
- 响应式布局、键盘焦点、弹窗焦点约束、减少动态效果支持。

## 演示边界

- 当前采用美元。角色价格系数为示例：汽修店 1.00，经销商 0.65，直营店 0.55。
- 配送费固定为示例 $12／单，自提免费。演示按全额付款，不启用定金或真实支付。
- 库存用于单次下单数量校验，不扣减库存、不接入仓库系统。
- 用户、认证、物流、运营指标、商品图片和适配关系均为演示数据。
- 账号隔离是浏览器内的数据隔离，没有服务端认证和授权能力。
- 数据使用 `localStorage` 保存到当前浏览器，无法跨浏览器或跨设备同步。
- 拼柜使用假设包装参数与预设装填系数。视图不代表实际物理装箱，不保证最优方案。
- C 端、供应商采购账号及真实业务规则待确认，暂不开放。

## 项目结构

```text
src/app.js          页面、交互与本机数据管理
src/domain.js       商品、价格、订单与拼柜规则
src/styles.css      视觉规范与响应式布局
assets/            本地配件示意图与品牌图标
tests/             核心业务规则测试
server.mjs         本机静态预览服务
srs/               需求与设计规范
```

本机预览服务只开放页面和静态资源，不开放需求、材料及 Git 文件。

## Docker 部署

使用独立 Nginx 容器，默认映射至 `127.0.0.1:5188`，不会启动 Node.js、数据库或队列服务。

```sh
TARGET_SHA=$(git rev-parse HEAD) RELEASE_ID=$(git rev-parse --short=12 HEAD) docker compose -p caucasus-demo up -d --build --wait
```

容器使用非 root 用户、只读文件系统和独立临时目录。宿主机可在测试站 HTTPS 配置中引入 `deploy/host-nginx-snippet.conf`，通过 `/caucasus/` 访问。页面资源使用相对路径，兼容根路径和该子路径。

`/release.txt` 返回构建提交 SHA，`/healthz` 为容器健康检查。Docker 镜像只包含页面、代码和配件资源，不包含合作材料、Git 元数据或本机采购记录。

## 多语种与专业审校

网站页眉和弹窗支持中文、English、ქართული（格鲁吉亚语）、Русский（俄语）。语言偏好在浏览器保存，切换时保留当前账号、采购清单、订单、筛选、弹窗与未提交表单。数字和日期采用相应 locale，业务时区为 `Asia/Tbilisi`；币种保持 USD，不进行汇率换算。

- `src/locales/messages.js`：四语文案配置，按稳定 `id` 维护；`source` 保留旧演示数据的原始词汇，`zh/en/ka/ru` 是可修改的显示文案。文案必须保持相同的花括号占位符，支持调整语序，不允许 HTML。
- `src/i18n.js`：语言选项、插值、格式化及旧数据展示适配。品牌、OE、SKU、车型代码不翻译；只本地化预设样例地址，不翻译客户填写内容。
- `srs/localization/四语文案对照校对表.xlsx`：397条配置文案、场景、变量含义、术语要点、四语修订栏、审校状态和审校人。
- `srs/localization/四语文案对照校对表.csv`：同内容的 UTF-8 BOM 数据表，供审校回写。

文案是按汽配B2B场景整理的本地化初稿，仍需母语汽配人员核对，不代表已完成专业审校。业务术语、计量单位、付款/物流语义和手机排版应一起核验。

运行 `npm run locales:export` 可从当前配置重新生成CSV。审校人员保留原文列，在修订栏填写建议，把通过的行设为“已确认”；回传CSV后运行 `npm run locales:import -- 文件.csv` 仅校验，加 `--apply` 才写入配置。导入会拒绝缺行、重复/未知键、改动原文、HTML或占位符不一致；所有校验通过后才一次性写入。导入不自动部署。

# 高加索汽配平台采购端需求草案

版本：V0.1 · 用于 POC 范围确认

来源：`../docs/高加索汽配B2B平台-合作沟通版.pptx` 第 8–14、16 页及项目需求讨论。范围冲突以最新讨论为准，尚未确定的商业规则单独标注。

## 1. 产品目标与边界

面向格鲁吉亚汽配采购场景，让买家能够找到适配配件、查看自己的采购价格、完成下单，并了解货物何时及如何交付。

系统划分为两端：

- **采购端**：所有买家共用，提供商品浏览、检索、采购下单和订单跟踪。
- **运营端**：负责商品上架、库存、调价、客户等级和业务配置。本次 POC 以结果展示为主，暂不建设完整管理流程。

POC 的重点是让采购流程可实际操作。库存、付款结果和物流节点可以使用预设数据，但页面之间的数据和状态应保持一致。

## 2. 用户角色与价格规则

### 2.1 买家角色

| 角色 | 采购端需求 | 当前确定程度 |
|---|---|---|
| 汽修店 | 查件、购买、查看库存与交付进度 | 已明确 |
| 经销商／批发商 | 按经销商价格采购，体现批量采购优势 | 已明确 |
| 直营店／自营门店 | 按内部价格采购 | 已明确 |
| C 端用户 | 使用同一采购入口 | 最新讨论纳入，具体价格及认证规则待定 |
| 供应商作为买家 | 有采购需求时使用同一入口 | 最新讨论纳入，价格归属待定 |

供应商在此处仅指采购身份。供应商入驻、供货报价、销售订单管理，不属于本次采购端范围。

### 2.2 差异化定价

**已确定：**

- 不同角色使用同一入口，登录后按账号属性显示对应采购价。
- 同一商品可以有不同角色价格。
- 汽修店可以直接下单，POC 暂不通过强制互斥保护经销商。
- 商品列表、详情、购物车及订单确认页，价格口径须一致。

**演示示例：**同一配件汽修店价 100 元、经销商价 65 元、直营店价 55 元。这些数字仅用于表达价差，不能视为正式价格或结算币种。

**尚未确定：**

- 采用独立角色价，还是“基准价 × 等级系数”。
- 是否按采购数量提供阶梯价。
- 若角色价、阶梯价、现货价和预售价同时存在，如何组合计算。
- C 端和供应商采购账号适用哪一档价格。

原材料要求未认证用户不可见价格，且不展示“登录查看价格”提示。该规则与最新讨论中的 C 端入口如何结合，需要确认。

## 3. POC 采购端功能

### 3.1 账号与身份

- 支持登录并识别当前买家角色。
- 显示企业／门店名称和账号身份。
- 根据身份加载对应价格。
- 不同账号查看各自的订单。

**POC 建议：**准备预设演示账号或演示专用身份切换，方便对比同一商品的不同价格。正式注册、资质提交和人工审核可后续建设。

### 3.2 商品浏览与检索

材料明确要求：

- 商品列表和详情浏览。
- 按 OE 号检索配件。
- 按“品牌—车型—代际”查找适配商品。
- 关键词搜索。
- 展示本地库存和预计到货时间。

**建议 POC 最小实现：**

- 分类浏览、关键词及单个 OE 号搜索。
- 基于演示数据的车型筛选。
- 商品详情显示名称、图片、SKU、OE 号、品牌、适配车型、规格、当前账号价格、库存及交付说明。
- 明确标识“现货”或“预售”。

车型适配在 POC 中使用预设数据。VIN 自动解析、图片识别查件不作为本次必做功能。

### 3.3 购物车与下单

- 选择商品和数量，加入购物车。
- 修改数量、删除商品，实时计算金额。
- 确认当前账号对应的采购价。
- 选择配送或到店自提。
- 配送时填写／选择收货信息，自提时选择提货地点。
- 显示商品金额、交付说明以及运费是否已确定。
- 提交后生成订单号，并能在订单列表和详情中查到。

**现货与预售混合采购：**

原材料要求混合加购后自动拆单。建议 POC 至少按现货、预售分别展示履约分组及预计交付时间；是否生成两个独立订单，需要在实现前确定。

### 3.4 现货、预售与自提

这三个概念应分别表达：

- **现货／预售**：商品供给类型。
- **配送／自提**：交付方式。
- **待付款／待发货等**：订单处理状态。

| 场景 | 买家需要看到的信息 | POC 处理 |
|---|---|---|
| 现货采购 | 本地库存、价格、预计交付时间 | 使用预设库存和交期 |
| 预售采购 | 预售价、预计到货日、付款说明、所属批次 | 模拟预售批次与进度 |
| 到店自提 | 提货地点、可提货时间、备货状态 | 展示待备货、待自提、已提货 |
| 配送订单 | 收货信息、配送进度、预计送达时间 | 展示模拟物流节点 |

原材料中的“现货 3 个工作日内交付”“预售 30–60 天”“定金 30%”属于已有方案条款，尚需确认是否沿用，POC 不应直接将其写成正式服务承诺。

### 3.5 订单列表与详情

- 查看当前账号订单。
- 按状态筛选，进入订单详情。
- 显示商品、数量、成交单价、金额、交付方式、地址／自提点。
- 显示付款状态、履约状态及预计交付时间。
- 预售订单显示批次和到货进度。
- 用时间轴展示物流信息。

**建议演示状态：**

- 配送：待付款、待核账、待发货、运输中、已完成。
- 自提：待备货、待自提、已提货。
- 预售履约节点：待采购／拼柜、已发运、清关中、已入本地仓、待配送／自提。

预售履约节点与付款状态分别显示，避免将“已付款”和“运输中”混为同一类状态。

### 3.6 付款展示

原材料采用“付款凭证上传、人工核账”，暂不接支付网关。

**建议 POC：**

- 展示应付金额和付款说明。
- 使用模拟付款／核账结果，支持完整下单演示。
- 是否加入付款凭证上传，单独确认。
- 本次不要求真实扣款、财务对账或在线退款。

### 3.7 我的账户

POC 最小范围：

- 当前账号、企业／门店及角色信息。
- 收货地址或自提信息。
- 我的订单入口。

原材料中的等级系数、账期额度及已占用额度，可作为后续能力；如在 POC 展示，应明确为示例数据。

## 4. 配套展示页面

### 4.1 运营数据大屏

大屏作为独立演示入口，面向合作方和运营人员。

**已明确需要展示：**

- 经销商数量及分布。
- 货源分配比例。
- 货柜组装／拼柜情况。

**可补充的演示指标：**

- 订单数量和采购金额。
- 现货、预售订单占比。
- 在途批次、预计到货情况。
- 热门配件或采购品类。

允许采用静态或半动态数据，通过地图、图表、货柜进度及动画呈现。指标之间需保持一致，并标注演示数据。本次无需支持真实上架、盘点或调价操作。

### 4.2 智能拼柜概念演示

展示如何依据配件体积、形状、重量和堆叠约束安排装箱。

**建议演示流程：**

1. 选择预设采购批次或商品清单。
2. 展示假设的包装尺寸、重量、可堆叠等参数。
3. 点击“模拟拼柜”。
4. 显示装箱示意、装载率、剩余空间及未装入商品。
5. 对比两种模拟方案。

POC 可以使用预设结果或简化计算。必须明确参数和结果为模拟，不将示意效果表述为已验证的最优装箱能力或真实节省金额。

单柜约 2 万美元仅作为讨论中的成本背景，不作为固定运价。

## 5. POC 页面清单与验收

### 页面清单

| 页面 | 核心内容 |
|---|---|
| 登录／演示身份入口 | 识别买家角色 |
| 商品列表 | 分类、检索、价格、供给类型 |
| 商品详情 | 适配信息、库存、交期、加购 |
| 购物车 | 数量修改、价格计算、现货／预售分组 |
| 订单确认 | 配送／自提、收货信息、金额、提交 |
| 下单结果 | 订单号和订单入口 |
| 我的订单 | 订单列表及状态筛选 |
| 订单详情 | 商品明细、付款状态、履约时间轴 |
| 我的账户 | 角色和基础资料 |
| 运营大屏 | 经销商、货源、货柜等指标 |
| 智能拼柜演示 | 参数、装箱示意及模拟结果 |

### 验收场景

1. 用汽修店、经销商、直营店账号查看同一商品，显示对应价格。
2. 汽修店可直接下单，无角色互斥拦截。
3. 通过关键词或 OE 号找到商品，查看适配信息后加入购物车。
4. 修改数量后，商品金额与订单确认金额一致。
5. 分别完成一笔配送订单和一笔自提订单。
6. 完成一笔预售订单，查看预计到货日与模拟履约进度。
7. 新订单能在当前账号订单列表中找到，刷新后仍可查看。
8. 不同账号的订单相互隔离。
9. 大屏与拼柜演示完整可展示，模拟数据有明确标识。

上述第 7、8 项是为形成可验收采购闭环补充的实现要求。

## 6. 后续能力与待确认事项

**原材料提出、建议放到后续正式版本：**

- 企业注册、资质审核及客户分级。
- 真实库存同步、采购、出入库和盘点。
- 付款凭证核账、在线支付、对账。
- 真实物流节点接入。
- 预售定金、尾款、延期提醒、取消及退款。
- 账期审批、额度占用和回款管理。
- 批量 OE 查询、清单询价、一键复购。
- VIN 解析、图片查件。
- 多语言和多国扩展。
- 基于真实物理参数的智能装箱优化。

原材料对批量询价等能力的分期表述并不完全一致，本次不据此自动纳入 POC。

**开始设计前需要确定的事项：**

| 事项 | 建议的 POC 默认方案 |
|---|---|
| 页面载体与语言 | 先做桌面 Web 演示；语言需按实际演示对象确认 |
| 演示角色 | 优先汽修店、经销商、直营店，C 端及供应商规则留待确认 |
| 价格与币种 | 用固定角色价演示；币种统一，正式定价另行确认 |
| 阶梯价 | 暂不叠加，避免与角色价规则混淆 |
| 付款方式 | 模拟付款结果，凭证上传作为可选项 |
| 混合采购 | 支持现货／预售分组展示，确认是否自动生成独立订单 |
| 物流与拼柜 | 预设数据和模拟节点，完整呈现流程 |
| 运营端深度 | 结果大屏及演示数据支持，完整后台后续建设 |

材料中的“30 家认证客户、3,000 个 SKU、10 笔真实核账交易”是正式业务阶段的验收目标，不适用于本次 POC。
